## Общая архитектура

Nuxt 4, Vue 3 Composition API, TypeScript strict, Pinia. CSS без сторонней визуальной библиотеки. API DTO генерируются из настоящего OpenAPI. SPA-рендеринг соответствует cookie-based Sanctum; авторизация и tenant не сериализуются в SSR.

`auth` layout: BrandPanel + форма. `default`: sidebar 220 px, header 76 px, содержимое и footer. Общие элементы: кнопки, поле с label/help/error/action, select, badge, card, alert, table, dialog, loading/empty/error/pending. Доменные компоненты используют эти примитивы вместо копирования полей и кнопок.

Страница владеет данными раздела; Pinia содержит только сессию/школу и глобальное уведомление. Middleware проверяет аутентификацию и роли. UI не рассчитывает серверные бизнес-правила генерации, moderation, sign-off или provenance.

## Адаптивность

- Вход 1440: брендовая панель 742 px, форма x814/y126/w550/h642. При промежуточных desktop-размерах используется grid, без абсолютного позиционирования формы.
- 768: верхняя зона 332 px, форма x132/y276/w504/h638. Карточка перекрывает нижнюю часть брендовой зоны на 56 px.
- 390: верхняя зона 252 px, форма x16/y224/w358/h620. На 360 ширина карточки 328 px, высота 620 px, брендовый заголовок 24 px и партнёрская плашка 232 px.
- Смена auth-композиции происходит ниже 1200 и 600 px — это выбранная интерполяция между контрольными макетами, не утверждение о наличии таких breakpoint-токенов в Figma.
- Workspace: ниже 1024 sidebar скрывается; на tablet горизонтальная compact-навигация, на mobile сетка 2×2 без горизонтального скролла. Контентные поля — 32 px desktop/tablet, 20 px mobile.
- Длинные ошибки и названия переносятся, таблица имеет собственную область прокрутки. Вход проверен на четырёх заданных ширинах; защищённый workspace ожидает интеграционной проверки с действующей сессией.

## Состояния и переходы

Форма: empty → native required/email validation → submitting (disabled, aria-busy) → ошибка API/поля или загрузка профиля. Пароль можно показать, не отправляя форму. Ошибка 422 не заменяет успешный экран. После входа tenant подтверждается сервером; при нескольких школах открывается выбор, после выхода — login. Защищённая локальная ссылка сохраняется как return path, внешние/двойные slash/backslash-ссылки отбрасываются.

Dialog использует `<dialog>.showModal()`: native focus trap, Escape, возврат фокуса, кнопка закрытия. Select — нативный, с keyboard-support. У кнопок hover/focus/disabled/loading. Сообщения используют alert/status, поля связаны с label и aria-describedby, есть skip-link.

Непосредственно прочитанные связи прототипа: `1:2590 → 1:2146` (календарь), `1:2594 → 1:639` (мероприятия), `1:2598 → 1:497` (школа), `1:2630 → 13:175` (конструктор), `72:493 → 1:2580` (демо), mobile `72:564 → 1:2348`. Последние две связи пока заменены честным диалогом отсутствующей серверной возможности. У отдельных login/recovery-элементов в полученной выборке reactions не обнаружены; требуемый рабочий auth flow определяется контрактом API.

Frontend-only: показ пароля, диалоги, native select, tab/accordion, промежуточные wizard-шаги, переключение визуального представления. Backend: login/logout/profile/tenant, выборка календаря/сценариев/традиций, сохранение, генерация и polling, ревизии и optimistic-lock, moderation, sign-off, экспорт, A/B-выбор, анкеты и метрики.

## Роли

`teacher` / `school_admin` относятся к выбранному tenant. `catalog_curator` / `system_admin` — системные роли. Школьный администратор не становится системным. Системная роль без членства не даёт доступ в школьный workspace. Все решения сервера приоритетнее frontend-проверок.

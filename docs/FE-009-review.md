# FE-009 — My Events, Scenario Archive & Safe Deletion

Завершение проверки: 2026-10-28. **PENDING INDEPENDENT REVIEW.** FE-010 не начат. Исходники Laravel и Figma не изменялись.

## Что реализовано

`/events` получает настоящий ScenarioListResponse: карточки, текущая ревизия, автоматическая модерация, даты, архивный статус, серверная пагинация, поиск, сортировка, загрузка/ошибка/пустое состояние и ручное обновление. Учитель видит доступные ему записи выбранной школы. Переходы ведут к существующим сценарию, редактору, экспорту и конструктору. Старые `/events/:id` и `/events/:id/export` перенаправляют к работающим страницам FE-007/008. Параметр `export=1` открывает существующий ExportPanel. В просмотр добавлена ссылка на сохранённый ScenarioRequest; после генерации есть путь к реестру.

Архивирование, восстановление и удаление имеют отдельные именованные подтверждения. Перед отправкой перечитывается сценарий; повторное нажатие блокируется. После успеха список загружается заново, включая коррекцию опустевшей последней страницы. Удаление не подменяется архивацией, физическое удаление не выполняется, восстановление soft-deleted записей не предлагается.

Смена школы, пользователя, роли или выход отменяют запросы, закрывают старый диалог и очищают список. Поздние ответы не применяются. Минимальная квитанция в sessionStorage содержит только ID пользователя/школы/сценария, действие и время. Название и содержимое сценария не сохраняются. После неизвестного результата/408/5xx нет автоматического повторного POST/DELETE: сначала GET-сверка, затем при необходимости отдельное явное новое подтверждение. Недоступное хранилище блокирует неотслеживаемую мутацию.

P2 FE-008 исправлен точечно: сетевые ошибки, 408/5xx, AbortError, повреждённый файл и checksum mismatch больше не обозначают документ как отозванный. Локальный запрет ставится при подтверждённом HTTP 401/403/404/409/410. Настоящий is_downloadable=false из свежей истории остаётся обязательным ограничением.

## Контракт и Figma

[Контракт API](fe009/api-contract.md) и [Figma inventory](fe009/figma-node-inventory.md) входят в поставку. Сохранены 13 high-fidelity contexts: список, пустое состояние и удаление на четырёх размерах, а также разграничение с ежегодной школьной традицией 97:1007. Архив и восстановление собраны из принятого UI-kit, поскольку отдельных кадров не найдено. Figma не редактировалась.

OpenAPI описывает только page/per_page. До использования контроллером и реальными HTTP подтверждены существующие q, is_archived, status и created_at asc/desc. Это серверная фильтрация всей доступной выборки, не поиск по загруженной странице. Даты и другие сортировки не выставлены в UI. Backend OpenAPI не менялся; добавлен локальный тип операции.

В списке нет автора, ScenarioRequest/GenerationRun ID, истории sign-off и актуальности fingerprint. Статус completed означает наличие записи подтверждения текущей ревизии, поэтому карточка не обещает актуальный допуск. Недостающие классы, участники и даты повода из Figma-примеров не выдуманы. Переход к запросу выполняется после чтения подробного сценария. GenerationRun доступен через действительный маршрут/квитанцию FE-006; обратное соответствие из списка не угадывается. Прямой переход из карточки к `?export=1` проверен в браузере: существующий ExportPanel открылся для v2 и запретил создание без подтверждения. Свидетельство — browser-export-link.json.

## Реальные HTTP и PostgreSQL

Основной [HTTP E2E](fe009/evidence/http-events.json): **PASS, 72 запроса**, исключительно localhost:8001 → app-test → school_events_test, роль school_test_user. Созданы собственные FE009 школы/пользователи/ScenarioRequest/GenerationRun/сценарии через настоящий Laravel MockLlmProvider. Рабочая БД не использовалась для мутаций.

Проверены появление в списке, пагинация и поиск записи вне загруженной страницы, статусы/сортировка/архивный фильтр, архивирование и восстановление. [PostgreSQL evidence](fe009/evidence/persistence-verification.json) сопоставляет before-archive, after-archive, after-restore и after-delete: сохранились revision payload SHA256, модерация, sign-off, экспорт и metadata артефакта; soft-delete оставил строку с deleted_at и её ревизии. Генерация и новый sign-off при восстановлении не создаются.

DELETE подписанного сценария возвращает 409 CANNOT_DELETE_SIGNED_OFF_SCENARIO. Дополнительный [HTTP-тест исторической подписи](fe009/evidence/http-historical-signoff.json) проверил текущую ревизию без sign-off при подписанной v1 — Laravel также вернул 409. v1 content/signoff сохранены. is_current является вычисляемым полем и закономерно меняется после появления v2; это не изменение исторического payload.

Другой учитель и другая школа получают 403 на прямой GET и archive/restore/delete. School_admin читает школьный список и архивирует/восстанавливает чужой подходящий сценарий. Системный пользователь без членства получает 403 от tenant middleware: проверка контроллера сама по себе была недостаточна. Исследовательский первый запуск, обнаруживший это условие, сохранён отдельно; итоговый E2E прошёл с фактическим контрактом.

После отзыва evidence сценарий архивирован и восстановлен. Сами эти операции не изменили проверки или подписи. История экспорта сообщает is_downloadable=false, GET download вернул 403 EXPORT_BLOCKED_BY_PROVENANCE_REVOCATION. Повторный допуск восстановлением не создаётся. GET удалённого сценария и restore удалённого сценария возвращают 404. После logout список возвращает 401.

## Визуальная приёмка

Снимки и фактические CSS-размеры: `fe009/screenshots/metadata.json`. Проверяются список, пустой список, архив, подтверждения архивации/восстановления/удаления, отказ удаления и мобильные карточки. Источник каждого снимка обозначен в metadata. Реальные карточки поступают из app-test; демоданные frontend не подменяют API. Пустой список снят под отдельной реальной тестовой учётной записью без сценариев. Финальная сверка final-persistence-check.json подтверждает неизменность ревизий, модерации, подписей и документов после UI-циклов; тестовый сценарий оставлен восстановленным.

Исследовательские снимки от 27 октября содержат измеренный tablet 767 px из-за DPR 0.84 старого браузерного окружения. При завершении 28 октября обязательные состояния пересняты с точными 1440/768/390/360 CSS px, DPR=1. Итоговые размеры фиксируются по DOM. Viewport устанавливается отдельным вызовом перед захватом, чтобы исключить кадр в предыдущем масштабе. Итоговые JPEG проверены по отношению сторон; матрица метаданных перечитана с диска перед каждым дополнением. Снимки JPEG имеют расширение .jpg. Внешние поля capture не являются горизонтальным переполнением страницы; scrollWidth проверяется отдельно.

## Ограничения

API не раскрывает актуальность provenance/sign-off в списке и не позволяет frontend доказать окончательный допуск. Наличие исторической подписи окончательно проверяет DELETE. Архивирование и восстановление не принимают If-Match/Idempotency-Key; frontend не добавляет несуществующие заголовки и не обещает транзакционных гарантий сверх Laravel. GET после неизвестного результата сообщает наблюдаемое состояние, а не доказательство того, что старый запрос никогда не выполнялся.

Soft-deleted запись не восстанавливается имеющимся restore endpoint. Содержимое в БД сохраняется, но пользовательской корзины/физического удаления здесь нет. Существующий backend export не проверяет is_archived отдельно; FE-008 консервативно блокирует создание нового экспорта архивного сценария, а скачивание решают история и серверный Gate. Никакие проверки или подписи автоматически не обновляются.

Глобальные счётчики вкладок и серверный фильтр по модерации отсутствуют, поэтому UI их не выдумывает. Общий total относится к текущему серверному запросу. Внешняя LLM не использовалась. Разделы A/B, пилотной аналитики и фиктивных примеров не реализованы. Исходники Laravel и Figma сохранены.

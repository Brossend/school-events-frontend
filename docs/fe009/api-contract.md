# FE-009 actual API contract

ScenarioController, Scenario/SoftDeletes, tenant middleware and `docs/openapi.yaml` were read without changing Laravel. Real responses and PostgreSQL state are in `evidence/`.

GET `/scenarios` documents page/per_page in OpenAPI. The controller additionally implements q (title ILIKE), is_archived (true/false/all), status (draft/completed/archived), from/to and sorting. Before frontend use, real HTTP verified page/per_page, q across unloaded pages, is_archived true/false/all, draft/completed and created_at asc/desc. `verified-query-contract.json` contains those responses. UI uses only those confirmed capabilities; dates and additional sort modes are not exposed. A local operation type override adds the existing parameters without editing generated OpenAPI or backend.

The default list excludes archived and soft-deleted rows. A teacher sees their own scenarios; school_admin sees school scenarios. Tenant middleware rejects a system user without school membership with 403 before the permissive controller branch. This was established by HTTP, not inferred solely from controller code. UI always requires an active school.

ScenarioListResponse contains id/title/status/is_archived/current_revision_id/optimistic_lock_version/moderation_status/timestamps/current_revision and pagination meta. It does not contain scenario author, saved request/run ID, all historical signoffs or provenance freshness. `completed` means a confirmed record exists on the current revision, without fingerprint freshness checks. The UI therefore avoids a final-use approval claim. Saved request navigation is added after reading the detailed scenario. A generation-run link is available only when an actual FE-006 receipt/run ID is known; no reverse mapping is guessed.

Archive and restore return 200 with id/title/status/is_archived/updated_at. They only toggle is_archived and updated_at; they do not create verification, signoff, revision or export records. Restore operates on archived visible scenarios; it does not restore soft-deleted rows. Existing export controller does not itself gate on is_archived; FE-008 conservatively blocks creating new exports in its archived UI. Existing downloads remain subject to fresh history and Laravel provenance gates.

DELETE returns 200 with data.message and sets deleted_at via SoftDeletes. It returns 409 CANNOT_DELETE_SIGNED_OFF_SCENARIO if ANY revision has ANY TeacherSignoff row, including historical records. This is stronger than the list's completed status. UI detects an obvious current signature during preflight, while Laravel remains authoritative for historical signatures and concurrent changes. The frontend never physically deletes data and never offers recovery of a deleted row. Missing scenarios return 404; tenant/author violations return 403.

All mutations re-read the target before confirmation and immediately before send. A minimal sessionStorage marker contains only user/school/scenario ID, action and timestamp; it contains no title or scenario content. Duplicate sends are locked. Context changes cancel work, close the dialog, clear the list and reject late results. A lost response/408/5xx/abort after send retains an uncertain marker; reopening first offers GET reconciliation. A separate new confirmation can be started only after a successful read and explicit user action. No mutation is automatically replayed; the shared transport retains its known-419 CSRF refresh behavior.

Archive/restore do not support If-Match or idempotency keys in this API. Read-after-unknown reports observed current state, not proof that an old request never ran. 404 after unknown DELETE means not found/unavailable; UI does not claim physical deletion. Storage failures prevent sending an untracked mutation.

FE-008 P2: only confirmed HTTP 401/403/404/409/410 refusals locally disable a download row. Network/408/5xx, AbortError and binary/checksum errors preserve the server availability flag and surface their error. A fresh history response with is_downloadable=false still disables it.

## Контракт и права

Подробное сравнение: [contract-notes.md](fe004/contract-notes.md). Главные расхождения:

1. OpenAPI не описывает is_archived query и поле is_archived в списке. Контроллер реально поддерживает false/true/all и отдаёт boolean. Добавлено узкое типизированное расширение; произвольные query не разрешены.
2. В OpenAPI у POST tradition/version отсутствует JSON content для 201; сервер возвращает data. Локальная корректировка позволяет получить ID созданной традиции без any и без изменения generated types.
3. Detail versions/active_version описаны generic object. Runtime адаптер уточняет реальный ответ; исторические object/array snapshots отображаются как неизменяемые данные. Неполная история не превращается в фиктивное нулевое количество.
4. Backend считает active_version последней по created_at, а не по максимальному academic_year. UI сохраняет этот порядок и прямо подписывает текущую по порядку создания.
5. Создание и редактирование имеют разные ограничения established_year/description; формы учитывают действительные Laravel validators. Дубль года — 422 TRADITION_VERSION_ALREADY_EXISTS, не 409. Общий транспорт сохраняет стандартную обработку прочих конфликтов.

Редактирование/архивация видны только автору, school_admin либо system_admin при совпадении активной школы с detail.school_id. Неавтор с teacher не получает эти кнопки. Создание ежегодной версии контроллер разрешает любому участнику текущей школы — это право не сужено до автора и не ошибочно расширено на чужой tenant. Сервер проверяет права независимо от кнопок.

Системному администратору также нужно членство для tenant middleware. Произвольного ввода schoolId и обхода этого ограничения нет. Архив не запрещает metadata/annual POST в текущем backend; UI сохраняет допустимые действия и предупреждает, что новая версия не восстанавливает традицию. Restore отсутствует на сервере.

## Изоляция и конкурентность

- Список использует только подтверждённый schoolId и X-School-Id. useTraditionsApi блокирует несовпадение captured schoolId с активной школой ещё до транспорта.
- Detail проверяет school_id из ответа до показа сведений и действий. Неподходящий UUID после смены школы даёт локальную ошибку/серверный 403, старые данные очищаются.
- Read-ресурсы переиспользуют createLatestResource/useSchoolResource: немедленная очистка, abort, generation/context checks. Формы закрываются при изменении школы/id маршрута.
- Мутации имеют отдельный createContextMutation: блокировка повторного submit, AbortSignal и сравнение user/school/role/route. Поздний success/error не закрывает форму и не показывает сообщение в другой школе. Запись после смены контекста автоматически не повторяется.
- Abort не является откатом транзакции: уже принятая сервером запись может завершиться. Новый tenant всегда загружается отдельно; при возврате нужно читать серверное состояние.
- Последовательный дубль года отклоняется сервером. Реальный параллельный тест использовал две отдельные сессии и дал **ровно один 201, один 422 и одну сохранённую версию**. История прежнего выпуска после редактирования метаданных и архивации осталась эквивалентной по JSON-содержимому.

В традициях нет серверного idempotency key для первоначального create. Клиент блокирует двойной submit и не повторяет мутацию при сетевой ошибке. Если ответ потерян, перед ручным повтором необходимо проверить список; exactly-once создание самой традиции не заявляется.

Рабочая БД не использовалась для создания/изменения традиций. Backend-исходники, конфигурация и миграции не менялись; рабочие seed/migrate не запускались.

Секрет тестовых аккаунтов вычислялся в памяти из тестового APP_KEY и runId через HMAC-SHA256, не записывался в отчёты/исходники. HTTP test имеет фиксированный origin 8001 и запускается лишь при FE004_ISOLATED=1; без этого он пропускается, случайного fallback на 8000 нет. Данные тестового контура оставлены для независимого просмотра.

Frontend временно запускался с NUXT_PUBLIC_API_ORIGIN=http://localhost:8001 для браузерного E2E. После проверки восстановлен обычный http://localhost:8000; этот адрес не зашит в feature-код, настоящий .env в архив не входит. Генератор fixtures можно передать через stdin контейнеру (`Get-Content tests/backend/fe004-fixtures.php -Raw | docker compose -f ../school/docker-compose.yml exec -T app-test php`) и сохранить его JSON.

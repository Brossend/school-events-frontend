# API-интеграция FE-001

Источник: `C:/Users/bross/WebstormProjects/school/docs/openapi.yaml` (OpenAPI 3.1, API 1.4.0), `api-contract.md`, `AuthController.php`, `LoginRequest.php`, `routes/api.php`, `config/cors.php`, `config/sanctum.php`. Backend прочитан, не изменён.

## Реализованные операции

| Операция | Использование |
|---|---|
| `GET /sanctum/csrf-cookie` | Инициализация перед первым изменяющим запросом и обновление при 419. Описано в api-contract.md; отдельный маршрут Sanctum вне `/api/v1`. |
| `POST /api/v1/auth/login` | Только email/password; сессионные cookie, без bearer token. |
| `GET /api/v1/auth/me` | Bootstrap при открытии SPA, ручное обновление профиля. |
| `GET /api/v1/tenant/current` | Подтверждение выбранной школы сервером. |
| `POST /api/v1/auth/logout` | Очистка Pinia после подтверждённого выхода. При сетевой ошибке профиль сохраняется и доступен повтор. |
| `GET /api/v1/system/status` | Системный статус куратора/администратора. |

Все браузерные запросы идут непосредственно в Laravel с `credentials: include` и `Accept: application/json`. Nitro используется только как штатный сервер Nuxt; нового backend/BFF/proxy нет. `ssr: false` исключает перенос приватных cookie и данных в SSR-кэш/HTML.

`XSRF-TOKEN` декодируется и передаётся как `X-XSRF-TOKEN`. Сессионная cookie остаётся под управлением Laravel/браузера. Токены, пароль и профиль не записываются в localStorage, sessionStorage или persist-плагин. Пароль очищается после успешного входа. Единственная повторная отправка мутации выполняется после 419; произвольные POST при сетевых/5xx ошибках не повторяются.

## Контекст школы

Членства берутся из сессии. Одна школа или отмеченная default подтверждается вызовом `/tenant/current`. Несколько школ без default требуют явного выбора в профиле. Идентификатор передаётся в заголовке, не внедряется в тело приватного запроса. Чужой идентификатор блокируется до запроса, окончательное решение всегда принимает backend.

Контекст меняется только после успешного ответа сервера. Обновление профиля сохраняет доступную выбранную школу. Содержимое рабочего пространства перемонтируется по ключу tenant, чтобы последующие страницы не показывали данные предыдущей школы. Системным пользователям без членства доступны профиль и системные разделы; школьные страницы требуют школьную роль.

## Ошибки

| Статус | Поведение |
|---|---|
| 401 | Очистка профиля/школы, возврат на вход с безопасным локальным redirect. |
| 403 | Сообщение об отсутствии доступа; роли в middleware также проверяются до открытия раздела. |
| 409 | Предложение обновить данные; автоматическое повторение изменения запрещено. |
| 419 | Один запрос CSRF-cookie и один повтор; бесконечного цикла нет. |
| 422 | `error.details` → ошибки полей; поддержан стандартный Laravel `errors`. |
| 429 | Сообщение о превышении числа попыток. |
| 5xx | Нейтральное сообщение, без утечки серверных внутренних деталей. |
| Сетевая ошибка | Явное сообщение о недоступности API и возможность повторить действие. |

Транспорт типизирует допустимые пути/методы, JSON-тела и успешные ответы из сгенерированных DTO. На FE-002 добавлены типизированные query/path parameters, URL-encoding и AbortSignal. Реально используются `/dashboard/summary`, `/calendar-events`, `/calendar-events/{id}` с подстановкой `params.id`. UI-only `month/view` в API не передаются. Отменённые запросы и ошибки устаревшего контекста школы не вызывают глобальные уведомления. Разделы со своим error/retry UI отключают дублирующее глобальное уведомление через `reportError: false`; 401 по-прежнему завершает сессию.

## Подтверждённые расхождения

1. **Закрыто в FE-012: `/auth/me` возвращает `{ data: { user, schools } }`, как login; `UserEnvelope` теперь соответствует этому формату в OpenAPI 1.5.0.** DTO перегенерированы. `parseSessionProfile(unknown)` продолжает проверять фактическую структуру и роли; проверка входящих данных остаётся необходимой. Историческое сравнение JSON сохранено в FE-001-final-review.md.
2. **Forgot password находится в `x-future-endpoints`, не в `paths` и не в routes/api.php.** Вызова нет, письмо не обещается, экран подтверждения отправки не имитируется.
3. **Demo login отсутствует.** Кнопка макета открывает объяснение, не создаёт вымышленную сессию и не подставляет учётные данные.
4. **Remember me отсутствует в LoginRequest и контракте; Auth::login вызывается без remember.** Чекбокс отключён с доступным пояснением.
5. Документы backend ссылаются на `61:1200`, `61:1250`, `108:1200` как на экраны профиля/системного доступа. В полученной структуре Design v1.0 эти screen-frame ID не подтверждены; реальный профиль школы — `1:497`. Профиль пользователя, селектор школы и системный статус в FE-001 используют существующие токены и layout, но не объявляются точными копиями несуществующих макетов.

## Проверка с реальным backend

При финальной проверке 25.10.2026 Docker восстановлен пользователем, существующий backend запущен без изменения исходников. Health вернул 200 с подключёнными PostgreSQL и Redis. Live-тест через настоящий API прошёл: CSRF cookie, login, me с двумя членствами, X-School-Id для обеих школ, CORS, отказы 401/403/422, реальный 419 с однократным восстановлением CSRF, logout и последующие 401. В браузере проверены настоящий вход, профиль, смена школы, обновление профиля, ограничения роли, выход и защита страницы после выхода. Подробные результаты и обезличенный JSON находятся в [финальном отчёте](FE-001-final-review.md) и `evidence/live-api-results.json`.

Unit-тесты используют изолированные fixtures; отдельный live-тест — реальные HTTP без mock-сервера. Длительное idle-истечение cookie и все аккаунтные состояния не считаются исчерпывающе проверенными. Роль куратора без школы покрыта unit-тестом, браузерная проверка этого отдельного аккаунта в финальный сценарий не входила.

# LLM-001.1 — Протокол покрытия историко-культурных утверждений

Текущий Gate: quality-2.3.6, detector: cultural-text-1.0.0. Это дополнительный механизм обнаружения, не замена JSON Schema, ScenarioSemanticValidator, ServerNormalizationService, модерации или Provenance Gate.

1. Рекурсивно перечисляются ВСЕ строковые листья JSON, включая неизвестные будущие разделы. Сохраняется путь $.field.index.field. Concept, этапы, реплики, роли, карточки с ответами, handouts, bullet_points, speaker_notes и методические рекомендации проходят один и тот же обход.
2. Только backend TrustedGenerationContext загружает выбранные CulturalClaim и актуальные evidence_records. Используются записи с живым verified_authentic и event_source_id; API пользователя не назначает эти статусы. Проверка повторяется при чтении ревизии, а не доверяет старому cached report.
3. Фрагменты разделяются по границам предложений/переносов. Только точное (кроме регистра/пробелов/конечной пунктуации) совпадение с claim_text получает узкий статус exact_supported_claim с claim ID и evidence source IDs/locator. Это НЕ whole-document authenticity. Точный библиографический заголовок/URL/локатор распознаётся отдельно и не считается новым фактом.
4. Детерминированные признаки — годы, календарные даты, исторические имена (в том числе Минин/Пожарский), ополчение/интервенты, век, архив/летопись, традиция/обряд/обычай и ряд исторических конструкций. Не совпавший с trusted claim фрагмент сохраняется с path, полным text, message, severity. Явные непредоставленные годы/имена блокируют генерацию и допускают только существующий ограниченный repair; остальные сигналы требуют review.
5. Даже при отсутствии сигналов или пустом cultural_claims всегда status=requires_review, complete=false, whole_document_verified=false. Нет конечного словаря, который гарантирует обнаружение всех перефразированных, недатированных или подразумеваемых утверждений. Отдельный LLM-detector не использован: он также не дал бы гарантии полноты и увеличил бы стоимость экспериментов.
6. Date-only claim о 4 ноября НЕ подтверждает историю 1612 года. Источник в одном месте не распространяет статус на соседние предложения, claimed_meaning, ответы или заметки. Снимок declared claims может иметь старое server_verification_status; свежий quality report и прежний live Provenance Gate не позволяют считать отозванный source актуальным.
7. Успешный GenerationRun хранит отчёт в sanitized_prompt.quality_gate рядом с prompt audit. Failed сохраняет ошибки с путём/текстом и usage. Для старых/отредактированных ревизий свежий отчёт вычисляется по неизменяемому содержанию; старые metadata и raw outputs не переписываются. Новых миграций не требуется.
8. blocksUse дополнительно запрещает Teacher Sign-Off, создание/скачивание экспорта и доступность культурного B для настоящих LiteLLM descendants с детерминированными blocking findings, включая старые результаты. Existing mock fixtures сохраняют прежнее поведение; API качества и предупреждение UI всё равно доступны. requires_review допускает осознанную проверку педагогом через прежний checklist; её выполнение не имитируется автоматикой.

Регрессии включают вставку исторического текста в десять разных путей, history в handout без structured claim, подтверждённую дату рядом с неподтверждённой историей, missing/revoked evidence и фрагмент без словарных признаков, который всё равно остаётся requires_review. Детерминированные тесты и реальные live-проверки имеют отдельные evidence; fixture не выдаётся за новый результат модели.

Ограничения: правила могут давать false positives на обсуждение истории как предмета проверки; точное сопоставление пропускает допустимые перефразы и намеренно не сертифицирует их. Неподтверждённое утверждение без признаков может не получить отдельный finding, но документ не получает automatic cultural PASS. Семантическая и экспертная оценка всего текста остаётся обязательной.

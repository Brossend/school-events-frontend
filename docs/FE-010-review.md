# FE-010 — A/B Scenario Comparison & Teacher Pilot Analytics

Техническое завершение: 2026-10-29. **PENDING INDEPENDENT REVIEW.** FE-011 не начат. Исходники Laravel, MockLlmProvider и Figma не изменялись.

## Реализованный frontend

`/comparisons` создаёт оба типа A/B из существующего ScenarioRequest текущей школы: universal_vs_personalized и cultural_context. Общие параметры загружаются из сохранённого запроса; ссылка на создание добавлена в его просмотр. Показаны действительные сохранённые сценарии A/B, этапы, роли, персонализация, педагогические отличия и присутствующие в ответе культурные ссылки. Нет копий одного объекта для имитации пары. История ведёт к существующим сравнениям и документам.

Выбор A/B требует причины и отдельного подтверждения. Перед POST повторно читаются сравнение, школа, статус и прежний выбор. 409 не переписывает предпочтение. После неизвестного результата выполняется только GET-сверка; автоматического повторного POST нет. Недоступный культурный B нельзя выбрать. Предпочтение педагога не называется доказанной статистической эффективностью.

`/pilot` показывает шесть серверных KPI, размер выборки, реальные знаменатели, покрытие экспертизой и отдельные статусы критериев. no_data, сбор анкет, 20 анкет с неполной экспертизой и завершение различаются. 5/20 проверок и 0 известных ошибок не превращаются в полный PASS. Завершение по серверу также не означает успех всех первых пяти KPI.

Уполномоченным пользователям доступны создание, перевыпуск и отзыв приглашения, анонимизированные участники, чтение анкеты по её ID, добавление новой версии экспертного заключения и скачивание JSON агрегатов. Обычный учитель не получает управление приглашениями/экспертизой/экспортом. Область куратора не раскрыта в профиле; глобальный доступ включается только после успешного GET scope=global. Региональный отказ остаётся отказом. Произвольный school_id не предлагается: используются активное членство и подтверждённая сервером глобальная область.

`/pilot/respond` — отдельная публичная анкета без обязательной Sanctum-авторизации и загрузки профиля. Поля, минимумы и nullable-значения взяты из FormRequest/PilotService. Процент сокращения времени приходит с сервера. После успеха токен очищается; после 409 форма переходит в терминальное состояние использованного приглашения. Неизвестный результат блокирует повторную отправку и направляет к организатору, поскольку публичного GET восстановления нет.

## Секреты, контекст и надёжность

Токен приглашения показывается только после ответа создания/перевыпуска и хранится в памяти смонтированной страницы. Копирование выполняется явной кнопкой. Токен не попадает в URL, localStorage, sessionStorage, console, аналитику, evidence или ZIP; при скрытии, смене вкладки/школы/сеанса и unmount очищается. Вкладки заблокированы во время выдачи токена, чтобы не потерять единственный ответ. Скриншоты делаются только без заполненного секретного поля и без открытой панели токена. Публичная страница задаёт no-referrer.

Существующие API-клиент, session/tenant, UI-kit и context guards сохранены. Устаревшие чтения отменяются и не применяются к новому контексту. Список, анкета, заключение, модальные действия и секрет очищаются при смене контекста. Двойной submit заблокирован. Ошибки предварительного GET отделены от неизвестного результата действительно отправленного POST. При неопределённости сначала выполняется доступный GET; утраченный токен этим не восстанавливается. Существующий подтверждённый 419/CSRF retry общего клиента не переписан.

Синтетический режим ограничен точным API http://localhost:8001 без credentials/path/query/hash. На обычном API нет переключателя синтетических агрегатов. По умолчанию include_synthetic отсутствует и в метриках, и в экспорте. Тестовые приглашения и сравнения маркируются автоматически, без пользовательского is_synthetic. В публичной анкете этот признак определяет сервер по приглашению. include_synthetic=1 означает включение обычных и синтетических записей вместе; тестовый UI прямо предупреждает об этом.

## Известные контрактные ограничения

1. ContextSnapshotBuilder записывает effective_status, а ScenarioComparisonService проверяет status. Поэтому проверенный HTTP fixture культурного сравнения не предоставляет B. Frontend сохраняет отказ и не исправляет snapshot/Mock/backend.
2. GET анкеты не возвращает эффективное заключение, статус/ошибки/замечания экспертизы или историю версий. Список участников не возвращает response_id, списка анкет нет. Можно читать анкету по полученному от участника ID и показать последний POST-ответ; нельзя обещать восстановление заключения после reload или автоматическую сверку неизвестного review POST.
3. Публичного GET статуса и idempotency key анкеты нет. Неизвестный результат нельзя подтвердить анонимно. Секрет утерянного ответа приглашения не восстанавливается: новый перевыпуск — отдельное подтверждённое действие.
4. Индекс/просмотр сравнения не раскрывает исходный ScenarioRequest и revision_id. Общие параметры доступны при создании из загруженного запроса; у исторической пары их нельзя достоверно восстановить. История не доказывает, что потерянный create не выполнялся. Сервер синхронно создаёт пары; queued/failed представления проверены frontend-тестами, а не выдаются за реально наблюдавшуюся очередь.
5. Операционные membership-права и аналитические полномочия различаются. Профиль не раскрывает scoped school directory и регионы куратора. Нет выдуманного выбора чужой школы. Для review сервер определяет школу по анкете; frontend предварительно проверяет доступ GET в текущем контексте.
6. Необязательный comparison_id публичной анкеты проверяется backend только как UUID, без полной проверки связи со школой/сценарием. Frontend не обещает соответствующую серверную гарантию. Нужен отдельный backend follow-up; здесь API не изменён.
7. Экспорт — только агрегированный JSON. XLSX/PDF и экспорт отдельных ответов не реализованы. Завершение по серверу не является выводом о статистической эффективности или успешности всех KPI. Автоматического повторного допуска источников/подписей нет.

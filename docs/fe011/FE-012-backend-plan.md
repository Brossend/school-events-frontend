# FE-012: минимальный план backend-исправлений

Это план, а не реализованный функционал. В FE-011 Laravel и Figma не менялись. Порядок: воспроизвести на собственных fixtures в school_events_test, внести минимальное изменение, проверить HTTP/PostgreSQL и регрессию, обновить OpenAPI, затем повторить frontend-приёмку. Рабочий каталог и внешнюю LLM не использовать как тестовую среду.

| Приоритет / проблема | Минимальная область изменения | Критерий приёмки |
| --- | --- | --- |
| 1. A/B культурного сценария: stored status расходится с effective_status | ScenarioComparisonService и существующий provenance service: проследить выбор cultural evidence, использовать единое актуальное серверное решение о допуске | На собственных approved/verified fixtures культурный B создаётся; source amendment/detach делает его недопустимым, даже при старом stored verified; обычный A не меняется. |
| 2. Потеря наблюдаемости экспертной проверки пилота | PilotResponseController/PilotService/routes: добавить минимальное авторизованное чтение действующего finding и его истории, согласовать способ получить response ID из административного списка | После POST и reload видны актуальная версия, эксперт, время и история; region/tenant/RBAC 403/404 проверены; прежняя версия не заменяет текущую, отсутствие finding не считается успешной экспертизой. |
| 3. comparison_id анкеты | CreatePilotResponseRequest + PilotService: existence и доменная проверка соответствия participant/school, доступности и завершённости пары в транзакции | Неизвестный UUID даёт 422 вместо FK/500; чужая/несовместимая пара отклоняется без сохранения анкеты и расходования одноразового приглашения; корректная пара принимается один раз. |
| 4. Неполные контракты и даты календаря | Существующие calendar resource/controller и OpenAPI: описать фактические envelopes /auth/me, школьные settings, PATCH source, attach/detach, pilot aggregates; определить и возвращать календарную дату/границы с часовым поясом | Contract tests сверяют реальный JSON со схемой; события показываются на правильной локальной дате, включая границу месяца/года. Невыданные даты не подменяются вымышленными. Перегенерировать клиент только после исправления схемы. |
| 5. MockLlmProvider: семейная конфигурация | MockLlmProvider и schema/validator family output: воспроизвести ошибку из FE006, исправить конкретное несоответствие contract | Тот же family request завершает generation/validation; индивидуальная/групповая конфигурации проходят регрессию. Внешняя production LLM не подключается. |
| 6. Пересечение страниц source queue | EventSourceController::reviewQueue: к created_at DESC добавить уникальный id DESC; сохранить существующий фильтр и RBAC | На 12+ источниках с одинаковым created_at страницы 1–3 не пересекаются, покрывают выборку один раз, meta корректна. Отдельно сохранить latest-review reviewed_at DESC,id DESC. |
| 7. Не вернулся ожидаемый audit после amendment | Сначала сопоставить исполняемый app-test runtime/версию/opcache/транзакцию с кодом EventSourceController и evidence service: создание audit уже присутствует в локальном controller | Источник/два claims: amendment отзывает допуск и создаёт ровно один ожидаемый audit на каждое ранее verified evidence; PostgreSQL и claim GET показывают одинаковые IDs. Не добавлять второй append вслепую. Reapproval не восстанавливает claims без explicit reverify. |
| 8. Нет атомарной защиты source/evidence от конкурентной записи | Отдельно согласовать минимальный version/ETag precondition и при необходимости Idempotency-Key для этих действующих операций; frontend GET-preflight не является заменой | Два куратора с одной версией: устаревший запрос получает 409 без записи; повтор одного ключа не создаёт двойную review/audit; контекст tenant/principal входит в область ключа. До отдельного решения гарантии не заявлять. |

Figma-only учебный год, класс, длительность и ресурсы не добавлять произвольными ключами settings. Сначала определить назначение, схему, валидацию и серверное применение; это отдельное продуктовое решение, а не условие скрытого расширения FE-011.

Финальный контроль FE-012 после реализации: real auth/tenant/RBAC, 401/403/404/409/419/422/5xx, unknown outcomes, export gate до/после revocation, полная frontend/backend регрессия и новая независимая приёмка. Никакой из перечисленных пунктов не выполнен в рамках FE-011.

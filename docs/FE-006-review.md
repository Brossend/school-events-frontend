# FE-006 — Asynchronous Scenario Generation & Results

Дата: 26.10.2026. **PENDING INDEPENDENT REVIEW**. FE-007 не начат. Backend и Figma не изменены.

Реализован путь сохранённый ScenarioRequest → явное подтверждение параметров → идемпотентный запуск → ограниченный опрос → чтение Scenario и точной ревизии. Существующий UI FE-001–005 сохранён. [Figma inventory](fe006/figma-node-inventory.md), [API](fe006/openapi.yaml), [сводка проверок](fe006/evidence/final-checks.json).

## Контракт и надёжность

Используются POST `/api/v1/scenario-requests/{id}/generate`, GET `/api/v1/generation-runs/{id}`, GET `/api/v1/scenarios/{id}`, GET `/api/v1/scenarios/{id}/revisions/{version}`, GET исходного запроса. Запуск без тела с обязательным UUID Idempotency-Key. Ответ 202 содержит generation_run_id/run_id; 409 содержит восстановительные ID в error.details. Поддержаны legacy replay ошибки с корневым run_id. Новый ключ не создаётся автоматически после потери ответа. Повтор с тем же ключом проверен реальным HTTP; повторная генерация допускается явно только после подтверждённого failed/timed_out. Ограничения попыток остаются серверными.

В localStorage хранятся только ключ, ID, время и контекст user/school/request. Содержимое сценария, cookies и токены не сохраняются. При недоступном storage известный run ID остаётся в памяти. После 23 часов интерфейс запрещает потенциально опасный повтор старого ключа (серверный TTL 24 часа). Потеря самого localStorage ограничивает восстановление: списка всех запросов/запусков API UI этого этапа не предоставляет.

Polling: последовательные GET с интервалом 2 секунды, сетевой backoff до 30 секунд, максимум 6 ошибок, максимум 5 минут наблюдения, 20 секунд на запрос. Скрытая вкладка приостанавливает новые GET. Смена маршрута, школы, пользователя и logout отменяют запросы и очищают данные; запоздавшие ответы игнорируются. Ручное обновление перечитывает существующий run. Локальный предел ожидания и сеть не меняют серверный статус на failed/timed_out. Endpoint отмены отсутствует.

HTTP 408 при сохранении FE-005 теперь считается неопределённым исходом POST: повторное создание блокируется. Исправление покрыто тестом. Транспорт сохраняет существующий механизм CSRF.

## Реальный JSON

В постановке упомянут `ScenarioRevision.content_json`; Laravel и действующий OpenAPI используют **content_payload**. GET Scenario содержит current_revision с общим JSON, детальный GET ревизии даёт content_payload. Сгенерированные API-типы сохранены; локальные runtime adapters уточняют JSON и проверяют ID, school_id, source_generation_run_id, номер и принадлежность ревизии. GenerationRun не содержит school_id, поэтому дополнительно читается его ScenarioRequest. Проверка активной школы выполняется и для system_admin.

Сохранённый пример: [generated-scenario.json](fe006/evidence/generated-scenario.json). Отображаются цель, задачи, механизм, ожидаемые результаты, подготовка, этапы/минуты/действия/реплики, роли, ресурсы, реквизит, карточки, раздаточные материалы, слайды, методические рекомендации и культурные утверждения. JSON выводится безопасным текстом, без v-html. Семь разделов доступны по локальному оглавлению с фокусом без повторной загрузки.

Действительные moderation_status включают verification_passed, verification_passed_with_warnings, verification_blocked, pending_verification, running, failed_engine. Автоматическая проверка и статус draft не означают человеческое согласование. Badge сопоставления отдельного доказательства требует attached authentic evidence с датой и locator; detached/rejected evidence не подтверждается. Синтетический проверенный источник fixture явно обозначен своим названием, внешний исторический факт этим тестом не удостоверяется.

## Браузер и адаптивность

Проверены 1440, 768, 390, 360 px: live queued, failed, completed, просмотр результата; fixture running/timed_out с видимой маркировкой. [Инвентарь скриншотов](fe006/evidence/screenshots.json), [измерения viewport](fe006/evidence/viewport-metrics.json). Горизонтального переполнения при финальных измерениях нет. Браузерные JPEG обрезают нативную полосу прокрутки: содержимое 375/345 px соответствует viewport 390/360 px. В ранней записи метрик queued повторён 390 вместо отдельной записи 360; compact capture сохранён с шириной содержимого 345 px. Длинные этапы, материалы, источники и FE-003 inspector проверены отдельно на 390 px. Full-page capture длинного результата недоступен в данном браузере: сохранены viewport и разделы, полного скриншота не заявляется.

В UI пройдены все пять шагов FE-005, сохранение, подтверждение запуска, реальная очередь, completed и чтение результата. Успешная UI-конфигурация: class_level / class_hour / historical_memory, 5 класс, 25 участников, 45 минут. Результат содержит реальные этапы 9/27/9 минут. После выбора школы B и возврата Back к сценарию A показан отказ без старого содержания. После logout прямая ссылка run переводит на login (UI и HTTP 401). Чтение scenario/revision чужим пользователем проверено HTTP 403. Прямые чужие UUID дополнительно проверены реальными HTTP-сессиями других пользователей.

## Ограничения

Живой UI-запуск family_community / class_hour / historical_memory, 90 минут завершился **failed, VALIDATION_FAILED, RULE_MECHANISM_ACTIVITY_NOT_FOUND** для «Лаборатория анализа исторических источников». Backend worker завершил обработку job, но бизнес-результат неуспешен и Scenario не создан. UI отображает понятную ошибку и реальные подробности; backend не исправлялся. Успешная классная конфигурация является отдельным запросом, а не подменой параметров неуспешного.

Реальная внешняя LLM, редактор ревизий, повторная модерация, Human Sign-Off, экспорт, отмена серверной задачи и каталог собственных запусков не реализованы. Выбор активной школы в принятом auth после полного reload возвращается к исходной школе; внутри SPA переключение корректно. Восстановление run по сохранённому ID поддержано, потеря браузерного хранилища ограничивает recovery. Нет независимой технической приёмки этим же исполнителем.

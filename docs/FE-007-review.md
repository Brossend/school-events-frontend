# FE-007 — Scenario Editor, Revisions, Moderation & Teacher Sign-Off

Дата передачи: 27.10.2026. **PENDING INDEPENDENT REVIEW**. FE-008 не начат. Laravel backend и Figma не изменены.

Реализован редактор существующего сценария: явное открытие поддержанных полей, PATCH текущей ревизии с optimistic lock, новая неизменяемая ревизия, чтение замечаний P0/P1, повторная модерация и отдельный чек-лист педагога. Режим чтения FE-006, локальное оглавление, provenance и SourceInspector сохранены.

## Интерфейс и данные

`/scenarios/:id` остаётся режимом чтения. `/scenarios/:id/edit` использует тот же ScenarioResult с локальными формами для concept, pedagogical_goal, трёх групп pedagogical_tasks, stages и materials. Можно изменить действия и реплики педагога, тип и длительность этапа, порядок этапов, содержание слайдов, карточек и раздаточных листов. ID этапов сохраняются вместе со связями activities. Поля других педагогических разделов не предлагаются для изменения.

Поддержаны validation state и сохранность ввода при 422, запрет двойной отправки, предупреждения перед уходом/reload, сброс форм и отмена чтения при смене школы/пользователя. Черновик хранится только в памяти вкладки. После ухода или перезагрузки восстановление несохранённого текста не обещается. Полный список ревизий API не предоставляет: доступен ввод известного номера и чтение этой версии; историческая версия не редактируется и не подтверждается.

Заголовок If-Match берётся из актуального `optimistic_lock_version` Scenario, не из version_number. Перед мутацией перечитывается сценарий; после 201 перечитываются новая ревизия и проверка. При 409 черновик сохраняется, доступно сравнение с серверной версией. Автоматического повтора PATCH с новым If-Match нет. Замена локального черновика серверной версией требует отдельного действия в диалоге.

Неопределённые результаты сети, 408, 5xx и собственного abort-deadline блокируют повторную мутацию до GET-сверки. Guard ограничивает цепочку операций 60 секундами. Чтение проверки идёт последовательно с интервалом 2 секунды, backoff до 30 секунд, максимумом 6 ошибок и 5 минут наблюдения; скрытая вкладка приостанавливает новые запросы. Смена контекста и уход отменяют чтение, запоздавшие результаты не применяются. Сетевой сбой не выдаётся за failed_engine.

Старый `/generation/:id` теперь перенаправляется на `/generation-runs/:id` с сохранением query и replace; устаревшая заглушка FE-006 удалена.

## Модерация и подтверждение

GET verifications показывает действительный статус, P0/P1, rule_code, target_path, message и suggested_fix. Различаются отсутствие проверки, running, passed, passed_with_warnings, blocked и failed_engine. Новая ревизия не наследует успешную модерацию и sign-off старой. Поля и верхний статус синхронизируются с результатом опроса выбранной ревизии.

Все три обязательных checkbox изначально пусты: safety_checked, timing_fit, cultural_context_approved. При P1 добавлен отдельный неотмеченный warnings_acknowledged. Есть teacher_notes. При несохранённых изменениях, исторической версии, P0, незавершённой проверке, ошибке движка, недостающих флагах или неизвестном исходе отправка блокируется. Системная роль сама по себе школьных прав UI не даёт; требуются школьная роль и принадлежность автора либо school_admin. Backend остаётся окончательным источником полномочий.

**Ограничение действующего read-contract:** GET не возвращает актуальный provenance fingerprint и действительность существующего sign-off. UI требует явную повторную проверку текущей ревизии в текущем сеансе и свежие GET, но не может заранее обнаружить отзыв evidence между GET и POST. В таком случае сервер возвращает MODERATION_REVERIFICATION_REQUIRED / MODERATION_BLOCKED_P0; готовность UI сбрасывается. Историческое подтверждение показывается отдельно. Сообщение текущего успеха появляется только после принятого POST и перечитывания и относится к моменту отправки. Наличие старой записи и status completed не объявляется бессрочным действительным допуском.

[Полная таблица контрактных расхождений](fe007/contract-notes.md): inline Laravel validation вместо названных Request-классов, generic object в OpenAPI, более строгая итоговая JSON schema, отсутствующий в OpenAPI warnings_acknowledged, null/pending response и разные enum moderation/verification. Использованы локальные typed overrides, сгенерированные API-типы не исправлялись вручную. Для полной предварительной проверки fingerprint требуется отдельное расширение read API; в этой поставке backend не изменялся.

У успешного HTTP-сценария четыре ревизии; SHA-256 содержимого версии 1 совпадает до и после. Предыдущие версии сохраняются, их sign-off не переносится на новую. Отдельный браузерный сценарий имеет собственную сохранённую редакцию и тестовое подтверждение; записи диагностического прогона не удалялись.

В браузере сохранена реальная редакция версии 3, выполнена повторная проверка, три исходно пустых пункта явно отмечены, отправлены тестовые заметки и получено фактическое подтверждение сервера. Это интеграционная проверка на синтетическом сценарии, не экспертная аттестация культурных сведений. Отмена ухода сохранила несохранённый текст; после явного ухода, выбора школы B и SPA Back редактор A отказал в доступе без старых данных. Выход вернул страницу login. Проверка неопределённого результата также наблюдалась при восстановлении app-test: UI заблокировал POST и предложил GET-сверку.

## Ограничения и FE-008

Нет полной истории через list API, добавления/удаления этапов вместе с несохраняемыми activities, хранения частного черновика после reload, клиентского вычисления достоверности фактов или fingerprint, автоматического слияния конфликта. Серверная ошибка MockLlmProvider для семейного масштаба отдельно [зарегистрирована](fe007/known-backend-issues.md) как BE-MOCK-FAMILY-001; Laravel не исправлялся.

PDF/DOCX/PPTX export UI, история скачиваний, A/B-сравнение и пилотная аналитика не реализованы. План FE-008 после независимой приёмки: сверить export/history API и Figma, подготовить создание export job только при действительном серверном допуске текущей ревизии, отслеживать очередь и ошибки, загружать готовые артефакты с повторной серверной проверкой provenance, проверить RBAC и недействительность старых export после изменения evidence. Этот план не означает начала FE-008.

После проверок app-test восстановлен к sync, frontend возвращён к штатному API localhost:8000; отдельный fixture server и production smoke server остановлены. Рабочая БД не использовалась для бизнес-мутаций.

Архив собирается `python scripts/package-release.py fe007`, проверяется `python scripts/verify-fe007-release.py`. Включены актуальные package/lock, source/UI-kit, assets, API/Figma, тесты, логи и evidence. Исключены node_modules, .nuxt, .output, .git, .idea, реальные .env, cookies, ключи, секреты и старые ZIP. SHA-256 вынесен в `.zip.sha256`; manifest проверяет каждый файл. Автоматическая проверка архива не заменяет независимую техническую приёмку FE-007.

Статус источника показан как **решение рецензента об источнике**. Он не превращается в подтверждение каждого связанного утверждения. Для evidence используется серверный `effective_status`, а не прежний сохранённый `verification_status`; `is_detached` имеет приоритет. Без локатора/цитаты зелёная отметка не выводится. Неизвестный статус отображается нейтрально. Верхнеуровневый «статус утверждения» не выдуман: сервер его не возвращает, решения относятся к конкретным свидетельствам.

Значения `pending`, `approved`, `rejected`, `requires_amendment` не смешаны с `unverified`, `verified_authentic`, `rejected_fake`. У source detail нет отдельного статуса revoked: видны последнее отклонение/требование доработки, а отзыв evidence показывается отдельно.

## Изоляция и RBAC

useProvenanceResource использует имеющийся createLatestResource: очистка старых данных, AbortController, номер запроса и сравнение контекста. Контекст включает authenticated/user.id/school.id/systemRole; изменение id маршрута и закрытие панели также отменяют запрос. Поздние success/error не восстанавливают данные предыдущего tenant/пользователя. X-School-Id передаётся общим API-клиентом; системная роль может читать каталог без школы, как разрешает Laravel.

Для новых маршрутов добавлено узкое access.catalog: членство активной школы либо роль catalog_curator/system_admin. Авторизация и дашборд не переписывались. Все окончательные решения о регионе/школе принимает сервер: доступ к чужим source/claim скрывается через 404, чужой school header даёт 403. Фронтенд не знает curated_region_codes из текущей сессии и не подменяет серверную проверку предположениями.

Чтобы ссылка возврата из detail работала и для системной роли без школы, `/calendar` использует тот же access.catalog/useProvenanceResource. Фильтры, URL, внешний вид и поведение учителя сохранены; системная роль получает только разрешённую сервером выборку без выдуманного school header. Дашборд `/` по-прежнему требует школу. Отдельной очереди каталога нет.
